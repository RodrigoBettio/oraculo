# Protocolos e APIs em System Design: REST, gRPC e GraphQL

## Resumo
Em **System Design**, explicitar como a comunicação acontece — seja entre cliente (frontend) e servidor (backend), ou entre microserviços internos — é um passo fundamental. Cada protocolo ou padrão de comunicação traz vantagens e desvantagens específicas:

1. **REST (Representational State Transfer)**: O padrão dominante para APIs públicas e de uso geral. Utiliza os métodos HTTP tradicionais (GET, POST, PUT, DELETE) e serialização comum em JSON/XML. Oferece alta maturidade e facilidade de integração.
2. **gRPC (Google Remote Procedure Call)**: Voltado para comunicação interna de alta performance entre microserviços. Suporta streaming bidirecional e transporte muito eficiente de dados binários (Protocol Buffers).
3. **GraphQL**: Desenvolvido pelo Facebook, permite ao cliente especificar exatamente a estrutura de dados desejada na resposta. Evita *over-fetching* (receber dados desnecessários) e *under-fetching* (necessitar de múltiplas requisições), além de ser excelente para federação de serviços.

---

## Principais Tópicos

- **REST**: Padrão de mercado, ideal para APIs abertas e públicas.
- **gRPC**: Foco em eficiência de rede, ideal para chamadas *inter-service*.
- **GraphQL**: Flexibilidade total no lado do cliente e agregação/federação de dados.
